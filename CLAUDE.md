# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Explorer is a native macOS file manager (SwiftUI, macOS 14+) modeled on Windows Explorer. The hybrid address bar (clickable breadcrumbs + editable text input with `⌘+L`) is the centerpiece feature — regressions there are release-blockers. Distribution is outside the Mac App Store; sandbox is disabled and the app reads the filesystem directly via `FileManager`.

For deeper, continuously-curated guidance, also read `.claude/napkin.md` at the start of each session.

## Build & Test

Open in Xcode: `open Explorer.xcodeproj`, run `Explorer` target with `⌘+R`, run tests with `⌘+U`.

CI-equivalent test command (use this when building/testing from the CLI):

```bash
xcodebuild test \
  -project Explorer.xcodeproj \
  -scheme Explorer \
  -destination 'platform=macOS' \
  -configuration Debug \
  CODE_SIGNING_ALLOWED=NO CODE_SIGN_IDENTITY="" \
  > /tmp/xcb.log 2>&1; echo exit=$?
grep -E "(BUILD SUCCEEDED|BUILD FAILED|error:|✘|✔)" /tmp/xcb.log
```

Notes:
- `run_in_background: true` for `xcodebuild` sometimes returns empty output — always redirect to a log and grep.
- Run a single test by adding `-only-testing:ExplorerTests/ResolvePathUseCaseTests/<methodName>`.
- CI runs on `macos-15` with Xcode 16 (`pbxproj` object format 77). Don't downgrade.
- Local dev builds skip code signing; public releases ship `codesign` (Developer ID) → `xcrun notarytool submit --wait` → `xcrun stapler staple` → GitHub Releases.

## Architecture

Clean Architecture, 3 layers, strict dependency direction `Domain ← Data` and `Domain ← Presentation`:

- `Explorer/Domain/` — entities (`Folder`), repository protocols (`FilesystemRepository`), and use cases (`ResolvePathUseCase`, `ListSubfoldersUseCase`). Use cases are concrete `struct`s, not protocols — fake the repository in tests, not the use case. Domain defines protocols; Data implements them.
- `Explorer/Data/` — concrete repositories (`LocalFilesystemRepository`). Only this layer (and `Folder` itself) touches raw `URL`. `final class` repository impls need `@unchecked Sendable` because `FileManager` isn't formally Sendable.
- `Explorer/Presentation/` — SwiftUI views and view models, organized by feature (`AddressBar/`, `Navigation/`). Talks in `Folder`, never `URL`. State uses `@Observable` + `@Bindable` (macOS 14+); never `@StateObject` / `@ObservedObject`.
- `Explorer/AppDependencies.swift` — composition root. Wires the live repository + use cases once at startup and passes them down via init parameters. The composition root MUST live at app root, not under `Presentation/`.

`Folder.path` is canonical: never has a trailing slash (except root `/`). Use `Folder.path` for comparisons — `URL.path(percentEncoded:)` is inconsistent across macOS versions (slash on macOS 15, no slash on macOS 26).

## Project File Mechanics

- Xcode 16 uses `PBXFileSystemSynchronizedRootGroup`: new files placed under `Explorer/`, `ExplorerTests/`, `ExplorerUITests/` are auto-included in their target. Do **not** edit `project.pbxproj` to register new source/test files.
- Shared scheme lives at `Explorer.xcodeproj/xcshareddata/xcschemes/Explorer.xcscheme` — CI depends on it. Don't move/delete.
- Deployment target is `MACOSX_DEPLOYMENT_TARGET = 14.0`. Newer-OS APIs require `if #available(macOS X, *) { … } else { fallback }`. Don't raise the deployment target without product approval (the `macos-15` CI runner can't test macOS 26+).

## Testing

- Use cases are tested with `ExplorerTests/Doubles/FakeFilesystemRepository.swift` — never real disk. Set `stubbedKinds[path] = .directory | .file | .missing`.
- Use synthetic paths under a synthetic home (e.g. `Folder(path: "/Users/test")`) — real OS paths like `/etc`, `/var`, `/tmp` get rewritten by `resolvingSymlinksInPath()` (`/etc` → `/private/etc`) and won't match stub keys.

## Conventions

- **Logging**: `os.Logger` only — `import OSLog` and define `private let log = Logger(subsystem: "Explorer", category: "<Category>")` per file. Never commit `print(...)`.
- **Indentation**: 2 spaces (enforced by `.editorconfig`); a Swift formatter runs on save.
- **No deprecated SwiftUI APIs**. Prefer `Table`, `NavigationSplitView`, `LazyVGrid`.
- **One top-level type per file**, except tightly-coupled `View` helpers.
- **SwiftData** is reserved for v1.1+ favorites/recents/preferences — never the source of truth for the filesystem.

## Git, Commits, PRs

- **Default branch is `develop`, not `main`**. Target PRs at `develop` (`gh pr create --base develop`).
- Conventional Commits, English, single descriptive line, no body unless strictly necessary, no `Co-authored-by` / `Generated by` trailers. Allowed types: `feat fix refactor perf style docs chore ci build test`.
- Stage files explicitly — never `git add -A` or `git add .`.
- PR titles validated by `pr-title.yml` (amannn/action-semantic-pull-request@v5); subject must start with lowercase.
- Multiple PR templates exist — when sending a PR-create URL, append `?template=<name>.md`.
- PR descriptions: Summary + Motivation only. **Do not** add a "Test plan" section.
- Update `CHANGELOG.md` under `[Unreleased]` (Added / Changed / Fixed / Removed) for user-visible changes.
- `PRD.md` and `TODO.md` are local-only (gitignored) — never `git add` them or reference them from public docs.
